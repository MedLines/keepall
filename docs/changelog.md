# Maintaining the changelog

The public Changelog records completed user-facing changes in Keepall. Entry data lives in `src/app/changelog/entries.ts`; `page.tsx` renders dated sections with New, Improved, and Fixed lists. `changelog.css` styles the timeline within the shared website shell.

Keep notes newest first. Use a stable entry ID and a `YYYY-MM-DD` date. Describe what someone can do, the problem a fix resolves, and material limits. Group related changes that reached main on the same day. Add Help links for instructions, with existing section IDs. Omit internal refactors, test-only changes, plans, and package versions that are not public release versions.

## Date and source policy

The reconstructed history uses **UTC dates when changes reached the public repository's main branch**. For merged branches, use the main merge date rather than an earlier author or branch-commit date. These dates establish the project chronology; they are not independently verified deployment timestamps. The earlier October 7 documentation-baseline entry has been replaced by the substantive feature history.

Future notes should accompany completed changes. Confirm they are in main, check the affected workflow, and record the source commit or pull request below. When a deployment date is independently known and is relevant to an entry, record that evidence too. Do not invent app versions, launch dates, or release announcements.

The layout reference was [Resurf's Changelogs](https://resurf.so/changelogs): chronological dates, feature titles, and short New/Improved sections. Keepall's content is independently derived from its own history and code.

## Claims deliberately excluded

There is no image cropping tool in the audited code. References to a closer crop are recognition guidance, and image layout cropping is display behavior. Video hover previews play short sampled clips automatically; pointer-position hover scrubbing is not implemented. Neither feature is claimed in the Changelog. No cloud sync, AI library assistant, native mobile app, or future release announcement is implied.

## Verification before landing

Run `pnpm exec eslint src/app/changelog` and `pnpm typecheck`. Open `/changelog` at phone and desktop widths, check the date/category hierarchy, and follow month links and Help anchors. Confirm its title, description, canonical, and social metadata remain present. Keep source evidence in this document when adding historical entries.
